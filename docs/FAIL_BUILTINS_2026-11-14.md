# تقرير D1 — قائمة builtins المفقودة من التشغيل الفعلي

## نطاق الدليل

تم جمع النتائج من تشغيل Host الفعلي عبر:

```text
python3 tools/run_engine_suite.py
```

واستُخدمت عينات Mario وPlataformas وShooter وZelda، بالإضافة إلى اختبارات النواة وGM82 corpus. هذا التقرير لا يستبدل اختبار Android الحقيقي؛ لوج الجهاز ما زال مطلوباً لإغلاق فجوة G14.

## النتيجة

| المؤشر | النتيجة |
|---|---:|
| اختبارات النواة | `54/54` |
| ألعاب Host | `4/4` |
| `UNMAPPED_GML_FN` قابلة للإجراء | `0` |
| `UNMAPPED_ACTION` قابلة للإجراء | `0` |
| رسائل `unimplemented` في لوج التشغيل | `0` |
| الفشل العام | `0` |

رسالة `test_auto_detect (missing file) PASS` ظهرت داخل اختبار مقصود لملف مفقود، وليست builtin أو action مفقودة، ولذلك لم تُدرج كفجوة تنفيذ.

## القرارات

لا توجد حالياً دفعة builtin جديدة يمكن تنفيذها بأمان وفق قاعدة FAIL-driven؛ تنفيذ أسماء عشوائية من قائمة GameMaker سيخالف الخطة وقد يغيّر التوافق دون دليل. تم إغلاق D1 على نطاق Host فقط بنتيجة قائمة فارغة.

الخطوة التالية المشروطة هي جمع `UNMAPPED_GML_FN` أو `UNMAPPED_ACTION` من `adb logcat` بعد تشغيل APK على جهاز Android حقيقي. أي اسم يظهر هناك سيُضاف إلى تقرير جديد، ثم يُنفذ ويُختبر منفرداً قبل الانتقال للاسم التالي.
