## نتيجة مقارنة نواة Android

نسخة `Nor-maker-8.2` تحتوي على نواة مبسطة قديمة (`gm82_assets.c`, `gm82_builtins.c`, ونسخة قديمة من `gml_vm.c` و`gm82_jni.c`). أما `Nr.mk.02` فتحتوي بالفعل على بنية أحدث ومقسّمة تشمل:

- قارئ GMK/GM82 مع اختبارات حدود وأمان.
- `gm82_gml_builtins.c` و`gm82_gml_eval.c` مع وظائف أوسع من المرجع.
- مسار bytecode تجريبي واختبارات lexer/parser/VM.
- materialization للغرف والكائنات، فكّ الصور والخلفيات، الصوت، الإدخال، الأحداث، particles وpaths.
- حمايات runtime ومسارات JNI وWebView المراجعة.

لذلك لم يتم استبدال أي ملف C بملف أقدم. النقل الحرفي لملفات المرجع كان سيؤدي إلى تراجع وفقدان وظائف، وليس إلى رفع التوافق.

## اختبارات مرجعية أُدمجت في بوابة الاختبار

المرجع يحتوي على اختبارين صغيرين مفيدين، وكانا موجودين مسبقًا في شجرة المشروع تحت `app/src/main/assets/core_validation/` لكنهما لم يكونا ضمن قائمة `tools/run_engine_suite.py`. تمت إضافتهما إلى المشغّل:

- `gml_do_until_test.c`: تكرار `do/until` مع `continue` و`break`.
- `gml_invoke_test.c`: استدعاء script مع `arg0` والتحقق من عزل scope بعد العودة.

هذه إضافة اختبارية فقط ولا تغيّر runtime أو ABI.

## ما لم يُنقل ولماذا

مشروع `Nor-maker-7` داخل الأرشيف هو Studio/Electron/TypeScript مستقل، وليس طبقة Android قابلة للنسخ إلى `Nr.mk.02`. كما أن التدقيق وجد مخاطر لا يجوز إدخالها:

- `utils/apkSigner.ts` يحتوي private RSA key مضمّنًا داخل المصدر.
- واجهات Studio تستخدم `eval` في مسارات تنفيذ GML/المعاينة.
- إعدادات البناء تسرّب مفاتيح API إلى bundle عند توفرها.
- منطق التوقيع القديم يتعارض مع pipeline التوقيع الإنتاجي الجديد المعتمد على JKS وGitHub Secrets.

بناءً على ذلك لم تُنقل ملفات Studio أو signer أو `temp_engine.js` أو أي مفاتيح/أسرار. يمكن تنفيذ دمج Studio لاحقًا فقط كمشروع منفصل بعد إعادة تصميم حدود الأمان وإزالة هذه الأسرار.

## التحقق

بعد إضافة اختبارات المرجع، يجب تشغيل:

```bash
python3 tools/run_engine_suite.py
```

نجاح الاختبارات المضيفة لا يثبت بناء APK أو الاختبار على جهاز Android؛ حالة Android ما زالت موثقة بصدق في `GAPS_HONEST.md`.

## قرار الدمج

تم دمج ما هو مفيد وقابل للتحقق: **اختبارات regression المرجعية فقط**. لم توجد وظيفة C آمنة ومفقودة تستحق نقلًا انتقائيًا من النسخ الثلاث دون تكرار أو تراجع معماري.
